# Publication Contents

[简体中文](publication-checklist.md)

This document summarizes the repository's design, verification, metrics, licensing, and checks, distinguishing independently reproducible deliverables from synthesis information supplied as a summary.

## Design and generation

- Chisel design, necessary common arithmetic, generation entry point, and pinned build dependencies are provided.
- The typical product contains eight SV modules and a complete file list; see [Native interface](interface.en.md) for top module and ports.
- Generation sizes are configurable. [Mathematical model](mathematical-model.en.md) fixes semantics; [Architecture](architecture.en.md) describes implementation.
- The product closure excludes verification ROMs, utilization tracking, and FPGA-specific primitives; memories retain generic synchronous1R1W behavior.

## Function and performance

- C and independent Python references cross-check coefficients, folded tables, and full MLE.
- Regenerated and bundled products separately pass functional, pause, backpressure, and in-flight reset tests.
- An intentionally incorrect reference triggers an explicit failure; regenerated and bundled product modules match.
- Ideal-interface measurements agree across three runs. Task latency, sustained throughput, and per-unit busy/idle definitions appear in [Performance](performance.en.md).
- Standalone reproduction passes; see [Reproduction](reproduction.en.md).

## Files and licensing

- Each project Markdown has separate English and Chinese files. The default README.md is English, README.zh-CN.md contains the complete Chinese translation, and other documents also have separate translations with reciprocal language links; body links target documents in the same language.
- Relative links use consistent document names within each language.
- Distributed payloads exclude original development-machine paths, credentials, internal identities, signatures, internal hashes/commit provenance, caches, and build logs.
- Normal commit identifiers and download-integrity metadata generated by Git and the hosting platform are platform metadata, not development-machine or credential information.
- The project uses the [MIT License](../LICENSE); reference attribution appears in [Third-party notices](third-party-notices.en.md).
- Only [Synthesis summary](synthesis-summary.en.md) is provided, without original DC materials.
- The Release attachment packages the complete repository content, excluding Git metadata, caches, build artifacts, and internal process files.
